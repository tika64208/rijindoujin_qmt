模块详解 · 每个部件干什么、怎么串起来、坏了会怎样

1竞价分析 App外部
rijindoujin_momentum (Android)
职责
09:25 集合竞价结束时冻结全市场快照，计算五因子涨停概率、可信度、V2 评分
输入
东财竞价接口（f2/f3/f5/f8/f10/f615/f630…）
输出
每日导出的 CSV，含原始字段 + 冻结评分
坏了会怎样
没有新 CSV → 推送的是旧名单 → 会买到昨天的票（所以看板 [5] 会标红）
2筛选推送待运行
push_from_export.py + bid_rules.py
职责
读最新 CSV，套用「高胜率」预设（竞价 2~4%、概率≥60、可信度≥70、评分≥35、市值 30~200 亿、股价 5~60、剔 ST、剔 warnFlag≥5），按概率降序取前 N
输入
export\竞价数据_*.csv
输出
GET /set?codes=... + out\push_YYYYMMDD.json 审计
坏了会怎样
名单不更新 → QMT 继续用上一次的名单，可能重复买同一批票
3名单服务—
list_server.py · 127.0.0.1:8765
职责
内存持有今日名单；接收 QMT 每秒心跳；聚合 QMT 日志导出 /status
输入
/set（推送）、/hb（心跳）
输出
/today.csv（给 QMT）、/status（给看板）
坏了会怎样
QMT 拉不到名单 → 买卖全停；看板也会断线
4买入策略—
autobuy_from_list.py · QMT 模型交易
职责
每秒轮询名单 + 握手；09:30:00-09:31:30 窗口内过滤（停牌/ST/涨停/无价）并按金额下单
输入
/today.csv、QMT 实时行情、账户可用资金
输出
passorder(23,1101,...) 委托 + [AUTO] 日志
坏了会怎样
当天不买（错过窗口就再也不买，因为每票每天只做一次决策）
5卖出策略—
autosell_close.py · QMT 模型交易
职责
每秒握手；14:50:00-14:56:30 把可用持仓全部卖出（配合"次日收盘卖"口径）
输入
QMT 持仓（m_nCanUseVolume）
输出
passorder(24,1101,...) 委托 + [SELL] 日志
坏了会怎样
持仓过夜，多承担一天风险
6计划任务—
Windows 任务计划 · QMT竞价推送
职责
每天 09:29:40 自动执行一次 push_from_export.py
输入
系统时钟
输出
触发一次推送
坏了会怎样
不自动推送 → 需要手动 启动.bat -Push

口径、限制与验证结论

买入口径09:30 开盘价附近（最新价委托）
卖出口径次日 14:50 收盘前清仓
仓位每只固定金额，最多 N 只，现金上限
费用回测未计手续费与滑点
4 天推演（185 笔入选 vs 1599 笔全市场样本）：当日纸面 −0.49% 超额、 次日开盘 +0.18%、次日收盘 +2.08%。样本少且含普涨日，实际期望需更多天数验证。
已知缺陷 1竞价换手率量纲错误，32% 权重因子失效
已知缺陷 2「剔涨停」判的是 warnFlag≥5，不是涨幅≥9.5%
已知缺陷 3市值取导出时点，跨档会使概率差 1~4 分
当前模式DRY_RUN（只打印不下单）
A 股 T+1：当日买入次一交易日才能卖，所以"当日收益"只作强弱参考，不能当收益。
