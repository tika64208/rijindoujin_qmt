# 竞价筛选 → QMT 自动买入 · 验证与设计

> 来源项目：`上游 Android 项目 rijindoujin_momentum`（Android/Kotlin 端侧量化系统）
> 目标：把 App 的「高胜率」竞价筛选逻辑提取出来，作为 QMT 自动买入的输入

---

## 一、验证结论（可复现）

### 1.1 验证方法

用 App 导出的 `export/竞价数据_2026-11-05.csv`（5,563 行，含全部原始字段 + App 计算结果列），
把 `BidStrategy.kt` 逐行翻译成 Python 后重新计算，与 CSV 里的 `概率 / 可信度 / 评分` 列逐行对比。

### 1.2 结果

| 口径 | 样本 | 概率一致 | 评分一致 | 可信度一致 |
|---|---|---|---|---|
| **预设区间（竞价 2~4%）** | 57 | **100.0%** | **100.0%** | 100.0% |
| 全样本 | 5,563 | 91.2% | 89.9% | **100.0%** |

全样本那 9% 的差异**全部**集中在「竞价涨幅 = 0」的行（未参与竞价的票），
而预设要求 2% ≤ 竞价涨幅 ≤ 4%，这类票根本进不了候选池。
→ **对实际使用路径而言，逻辑提取是精确的。**

### 1.3 值得记录的三个实现缺陷（原样保留，不做修正）

| # | 缺陷 | 影响 |
|---|---|---|
| 1 | **竞价换手率量纲错误**：`成交量(手) × 价格 ÷ (市值元 × 100)` 结果恒为 ~1e-6，永远小于 0.08 阈值 | 「竞价活跃度」因子恒取 0.3 档，占总权重 32% 的因子实际失效 |
| 2 | **「剔涨停」判据是 `warnFlag ≥ 5`**，不是涨幅 ≥ 9.5% | 触板但 warnFlag=4 的票（如 2026-11-18 的泰嘉、奥雅、行云）仍会入选 |
| 3 | **市值取导出时点的值**，与 09:29 评分时点可能不同 | 跨档时概率差 1~4 分；因此必须以 App 冻结评分为准，不能事后重算 |

## 二、提取出的规则（精确描述）

### 2.1 五因子涨停概率（权重 34/32/17/11/6）

```
因子1 竞价涨幅(34%)  3~5.5%→1.0 | ≥2→0.88 | ≥1.5→0.65 | >0→0.4 | 否则 0.1
因子2 竞价活跃度(32%) 换手≥0.8→1.0 | ≥0.4→0.88 | ≥0.2→0.72 | ≥0.08→0.5 | >0→0.3 | 否则 0.1   ← 实际恒为 0.3
因子3 异动等级(17%)   warnFlag 5→1.0 | 4→0.85 | 3→0.6 | 否则 0.18
因子4 市值(11%)       <30亿→1.0 | <60→0.88 | <120→0.68 | <250→0.45 | 否则 0.22
因子5 盘口动量(6%)    3~9.5%→0.9 | ≥1→0.65 | ≥0→0.4 | >-3→0.25 | 否则 0.15

概率 = clamp(round(加权和 × 100), 5, 95)
```

### 2.2 可信度

```
conf = 65 + 10(warnFlag≥4) + 8(换手≥0.4) + 7(竞价涨幅 2~6.5)
conf = clamp(conf, 55, 90)
```

### 2.3 V2 评分（0~100）

```
评分 = 竞价(≤50) + 涨幅(≤20) + 异动(20/16/10/0) + 量能(≤10)
  竞价 = min(竞价涨幅/9, 1) × 50
  涨幅 = min(有效涨幅/10, 1) × 20
  异动 = warnFlag 5→20 | 4→16 | 竞价涨幅≥4→10 | 否则 0
  量能 = min(估算竞价量/200000, 1) × 10
```

### 2.4 「高胜率」预设（HIGH_WIN_RATE）

| 条件 | 值 |
|---|---|
| 竞价涨幅 | 2.0% ~ 4.0% |
| 概率 | ≥ 60 |
| 可信度 | ≥ 70 |
| 评分 | ≥ 35 |
| 市值 | 30 ~ 200 亿 |
| 股价 | 5 ~ 60 元 |
| 剔除 | ST/停牌、warnFlag ≥ 5 |
| 市场 | 沪主板 + 创业板 + 科创板 |
| 排序 | 概率降序，同分按代码升序 |

### 2.5 买入口径（OpenBuyCalculator）

- 买入价 = **9:25 集合竞价撮合出的开盘价**
- 估值价 = 当前最新价（收盘后即收盘价）
- 等权买入，组合收益 = 各票涨跌幅算术平均，不含费用与滑点

## 三、数据流设计

```
09:25  竞价分析 App 冻结 09:30 档案（评分不可覆盖）
   │
   ├─> export/竞价数据_YYYY-MM-DD.csv   （已有，每日导出）
   │
09:29:40  push_from_export.py
   │      · 读最新导出 CSV
   │      · 套用 HIGH_WIN_RATE 预设
   │      · 优先使用 App 冻结评分（app_prob/conf/score），缺失才重算
   │      · 按概率降序取前 N
   │      · GET http://127.0.0.1:8765/set?codes=...
   │      · 写审计 out/push_YYYYMMDD.json
   │      · 回读校验
   ▼
09:30:00  list_server.py（常驻，127.0.0.1:8765）把名单挂在内存
   ▼
09:30:00~09:31:30  QMT 策略 autobuy_from_list.py
          · 每秒轮询一次窗口
          · GET /today.csv
          · 过滤：停牌(volume=0)/ST/涨停(现价≥涨停价×0.999)/无价格
          · 每只固定金额、最多 N 只、现金上限、100 股取整
          · passorder(23, 1101, ...) 下单 + 日志
```

### 为什么走 HTTP

QMT 策略沙箱**禁止文件 IO**（`Forbidden fileIO`），但**允许网络**（已实测 `HTTP 200` 每秒可取）。
板块文件方案需要重启客户端才刷新，`load_stk_list` 是"读走即改名"的私有投递通道，均不可用。

## 四、组件清单

| 文件 | 位置 | 作用 |
|---|---|---|
| `bid_rules.py` | 本目录 | 提取的规则模块（概率/可信度/评分/过滤/排序），已回归验证 |
| `push_from_export.py` | 本目录 | 读导出 CSV → 预设筛选 → 推送名单 |
| `list_server.py` | 本目录 | 常驻 HTTP 服务，向 QMT 发布名单 |
| `autobuy_from_list.py` | 本目录 | QMT 策略：窗口内拉名单并下单 |
| `out/push_YYYYMMDD.json` | 本目录 | 每日审计（源文件、入选数、推送明细） |

## 五、参数与开关

### push_from_export.py

| 参数 | 默认 | 说明 |
|---|---|---|
| `--top` | 5 | 最多推送几只（按概率降序） |
| `--date` | 最新 | 指定日期 `20261110` |
| `--file` | 最新 | 指定 CSV 路径 |
| `--dry` | 关 | 只打印不推送 |

### autobuy_from_list.py

| 参数 | 默认 | 说明 |
|---|---|---|
| `WIN_START / WIN_END` | 093000 / 093130 | 下单时间窗 |
| `AMOUNT` | 100000 | 每只金额 |
| `MAX_BUY` | 5 | 最多买几只 |
| `DRY_RUN` | True | 空跑开关（首次务必保持 True） |

## 六、实测记录

| 日期 | 全市场 | 预设入选 | 推送 | 结果 |
|---|---|---|---|---|
| 2026-11-05 | 5,563 | 9 | — | 验证用 |
| 2026-11-10 | 5,563 | **105** | 前 5 | 推送成功，回读一致 |

> 注意：预设单日可入选上百只（11-10 为 105 只），因此 **top-N 与排序规则是核心参数**，
> 不能简单"全买"。同概率时按代码排序会导致选择偏向小号段，建议改为「概率降序 → 评分降序 → 代码」。

## 七、风险与待决

### 7.1 已知风险

| 风险 | 说明 | 缓解 |
|---|---|---|
| 竞价快照 ≠ 成交价 | 09:29 评分、09:30 下单，价格已变（11-18 行云竞价 +2.75%，开盘后 +14.18%） | 涨停/高开过滤 + 限价保护 |
| 预设本身期望不高 | 11-18 当天 31 只，开盘后平均 **−1.45%**，仅 3 只封板赚钱 | 先 DRY_RUN 跑 5~10 个交易日，用审计 JSON 统计真实胜率再上实盘 |
| T+1 | 当天买次日才能卖 | 需配套卖出策略 |
| 服务单点 | list_server 未启动则拉不到名单 | 策略端失败重试 + 告警日志 |
| 审计缺失 | 只推代码不推评分，事后无法复盘 | 已落 `out/push_*.json` |

### 7.2 待拍板

1. **top-N 取几只**（建议 3）
2. **同概率如何排序**（建议 概率 → 评分 → 代码）
3. **卖出规则**：次日开盘卖 / 次日收盘卖 / +3% 止盈 −2% 止损
4. **是否等权**（每只固定金额 vs 按概率加权）
5. **是否需要盘中止损**（跌破开盘价 −2% 卖出）
